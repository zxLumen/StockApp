# CI build & deploy 连续失败定位与修复（2026-11-08）

> 范围：只修 `docker-publish.yml` 的 deploy job；业务代码未改（触发验证仅改了一行注释）。

## TL;DR

- **根因不是密钥，而是 `SERVER_HOST` 还指向 10-21 已下线的旧服务器 `43.161.222.62`。**
  GitHub Actions 一直在 SSH 旧机，旧机上没有 stock 部署公钥，所以每次都
  `ssh: unable to authenticate`；docker job 正常，镜像已推到 GHCR，但从未部署。
- 修复：服务器新增一把专用 ed25519 key（强制命令绑定到本仓 deploy 脚本），
  `SERVER_DEPLOY_KEY` 换新，`SERVER_HOST` 改为 `stock.zxlumen.cn`。
- 结果：`docker` + `deploy` 两个 job 均 success；容器镜像 digest 与本次 SHA tag
  一致；站点 200；普通 push 自动触发也成功。
- 观察窗内（08:24）上游又 push 了 `cedcea2`，run `42429525495` 自动部署成功，
  线上镜像随之更新为 `sha256:3a741951…`；详见「上线后观察」。

## 只读定位过程

1. 服务器迁移记录：`/home/ubuntu/migration/MIGRATION.md` 写明
   **旧机 `43.161.222.62`**；当前机公网 IP 为 `103.205.240.62`，
   `stock.zxlumen.cn → 103.205.240.62`。
2. `~/.ssh/known_hosts` 里 `43.161.222.62` 的 host key 与现在扫描结果不一致，
   `ssh-keyscan 43.161.222.62` 得到的是另一台机器；该机 SSH 直接
   `Permission denied (publickey,password)`。
3. 用服务器上已有的 stock 私钥测试：
   - `ssh -i ~/.ssh/stockapp_ci_deploy ubuntu@stock.zxlumen.cn …` → 公钥认证成功，
     强制命令进入 `stock-ci-run.sh`；
   - `ssh -i ~/.ssh/stockapp_ci_deploy ubuntu@43.161.222.62 …` → `Permission denied`。
4. 结论：密钥本身可用，失败发生在 **连错主机**。`SERVER_HOST` 最后更新时间
   （10-06）早于迁移（10-21），与 10-22 起开始全量 failure 的时间线吻合。

> 备注：`authorized_keys` 里旧 stock key 的 `command=` 指向
> `/home/ubuntu/zxLumen-Blog/docker/stock-ci-run.sh`，脚本会从 GitHub 再取最新
> `deploy/stock-ci-run.sh` 执行，所以旧 key 功能上可用；本次按任务要求把新 key
> 绑定到 `/home/ubuntu/Projects/StockApp/deploy/stock-ci-run.sh`，旧 key 全部保留。

## 上线后观察

**观察窗：2026-11-08 08:14:00 – 08:29:04（+08，15 分钟，15 个采样点）。**

- 15/15 采样 `http=200`（每分钟 curl 一次），容器 `restarts=0`；容器日志无
  `error/exception/fatal`，Caddy 侧 stock 5xx = 0。
- 08:14–08:24 容器 `StartedAt=2026-11-08T00:13:37.179968716Z`，即 run
  `42428704329` 部署的镜像 `sha256:62fe5b0d…`。
- **08:24:28Z 发生一次非本任务触发的新部署**：上游 commit `cedcea2`
  （“部署前为运行中镜像打 rollback tag 并保留最近 3 个”）push 触发 run
  `42429525495`，`docker` / `deploy` 均 success；服务器拉取并启动镜像
  `sha256:3a741951…`，容器被 recreate，`StartedAt` 变为
  `2026-11-08T00:24:28.74275428Z`。

## 回滚

### 1) 还原 SSH 授权（撤销新 key，恢复旧 5 条）

```bash
cp ~/.ssh/authorized_keys.bak-20261108 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
# 备份 sha256: 2f227123089df81fa0d0d26abed4535c9eb3810ebc9474f429a4084f6301d15b
```

### 2) 还原 GitHub secrets

```bash
# SERVER_DEPLOY_KEY 还原为上一版私钥（对应 authorized_keys 中的
# stockapp-gh-actions-deploy-20261107）
gh secret set SERVER_DEPLOY_KEY < ~/.ssh/stockapp_ci_deploy

# SERVER_HOST 还原为修复前的旧值（注意：该值已失效，仅用于精确回滚）
gh secret set SERVER_HOST --body '43.161.222.62'
```

### 3) 还原线上镜像（修复前手工版本）

```bash
sudo docker pull ghcr.io/zxlumen/stock-web@sha256:c99ba00093e8eee8d03e2b144470365446062e0c7bc8d26a7754d886b6e931bf
sudo docker tag  ghcr.io/zxlumen/stock-web@sha256:c99ba00093e8eee8d03e2b144470365446062e0c7bc8d26a7754d886b6e931bf \
                 ghcr.io/zxlumen/stock-web:latest
cd /home/ubuntu/zxLumen-Blog/docker
sudo env STOCK_TAG=latest docker compose up -d stock
```

### 4) 撤销触发用注释提交（可选）

```bash
git revert --no-edit dff92bf
git push origin main
```

## 遗留 / 注意

- `authorized_keys` 中仍有 douyu 个人 key 和 2 把旧 stock key；按要求未删。
