# 双链路 / B 策略近期亏损分析（观察日 2026-10-12）

> 口径：线上「模拟推荐持仓」`/api/positions`（每只 ¥10,000 等权、移动加权成本、盯市）。
> 相关留档：`docs/runs/B/eval-20261006/`、`docs/runs/dual/eval-20261007/`。
> 冻结参数：`web/config/model.json`（`b-2024-train-abs`）。

## TL;DR

线上双链路当前 **≈ -5.7%（收盘口径）/ -6.2%（盘中实时）**，**与 B 完全相同**；
A 链 ≈ -0.2%。基准沪深300 同期仅 -0.9%（至 10-09），但科技类指数
**科创50 -4.75%、创业板指 -2.93%**。

结论：**这不是一个 bug，而是「小样本 + 单一板块集中 + 均值回归策略在下跌 regime」的叠加**，
和留档评估"看着不错"并不矛盾——评估的窗口是反弹窗、口径是逐票持有期横截面均值。

## 3. 不一致的根因（分层）

1. **窗口 & regime 不同（最主要）**
   - 评估的正收益集中在反弹窗（2024-09、2025-08、2026-04 等）；线上是 3 天回调、
     且科技/存储板块领跌。同一个模型，regime 反了结果就反。

2. **样本极小 + 单一板块集中**
   - 线上前瞻只有 3 个交易日、16 只；等于**对一个板块下注一次**，没有分散。
   - 评估的"均超额"是每天 ~10 只、跨数月做横截面平均，**天然抹平了这种集中度风险**。

3. **策略本质是均值回归（超跌反买）**
   - 冻结权重：`reversal 0.2 / midRev 0.4 / event 0.3 / turnStd 0.5 / q 0.3`，
     `objective.maxDeviation 15 / devHi 40`。它挑的就是**跌幅最深的股票**。
   - 09-30 基日，存储股 `chg5 -11%~-33%、dev -10%~-33%、beta 2~4` → 全部命中；
     节后继续阴跌 → **接飞刀**。

4. **模型切换，线上首日即"新性格"**
   - `recommend/*.bak`（2026-07~09，旧管线）挑的是 **低波蓝筹**（长江电力/银行/茅台，vol≈0.008）。
   - `config/model.json`（`b-2024-train-abs`，2026-10-06 冻结）落到线上后，
     10-08 起突然变成**高 beta 超跌股**。用户记忆里"评估不错"是**新模型在有利窗口**的成绩；
     新模型的**头几天线上**恰好是这批存储股。

5. **节后基日滞后（放大伤害）**
   - 10-08 的 `basisDate = 2026-09-30`（国庆前），但入场锚在 **10-08 开盘**。
     信号在 09-30 生成、隔了 5 个交易日的长假才建仓，**信号已衰减 / 方向已错**。

6. **评估与线上口径不同**
   - 评估＝逐票"持有期收益的横截面均值"；线上＝固定 ¥1 万等权、逐日盯市的组合。
     名称高度相关时，两种口径会显著分叉。

7. **盯市数据日期不齐（待修）**
   - 组合里个股日K 最后是 **10-09**，而基准已到 **10-12**；盘中用实时价才对齐。
     盘后展示会出现"个股停在上个交易日 vs 基准当天"的错配（影响约百分位以内）。

## 4. 评估自身已注明的局限（引自留档）

- `dual/eval-20261007`：**验证→测试排序反转**，"短验证窗的选择风险"。
- `B/eval-20261006`：**optimize-factors 与生产 eval-backtest 口径不一致**（"待统一"）。
- `DATA-AVAILABILITY.md`：**幸存者偏差**（宇宙用当前成分股回溯）、2024~2025 新闻覆盖偏薄 → 历史偏乐观。
- `dual/eval`：测试窗 A 数据用 10-07 管线重生成，与训/验旧批**不同源**。

## 5. 建议（按优先级）

1. **开集中度上限**：`config/model.json` 的 `select.maxPerIndustry` 当前是 **99（等于关闭）**。
   改成 `2~3` 即可直接掐掉"半个组合押存储"的问题（这本就是"不写死"清单里的可训练参数）。
   → **已于 2026-10-12 处置：定为 3，见 §7。**
2. **B 的下跌 regime 护栏**：`tilt=0` 只把链路切到 B，但 B 恰恰是"越跌越买"。
   考虑在强下跌（低 tilt / 板块普跌）下**降暴露或空仓**，别让"保守链"承担全部下行 beta。
3. **评估口径升级**：按**组合等权**输出收益/回撤/波动，而不是逐票横截面均值；补**滚动窗口**与**最差回撤**，
   并显式区分"板块 beta"与"选股 alpha"（例如相对同板块指数的超额）。
4. **节后基日**：长假首个交易日的推荐，基日与入场日的错位要单独处理（或提示该日信号已过期）。
   → **已于 2026-10-12 处置（只标注 + 评估分档，不改交易），见 §8。**
5. **别用 3 天定生死**：把 `recommend-ai-fwd` / `recommend-factors-fwd` 攒到 **≥1 个月（≥20 个交易日）**
   再做前瞻判定；现在下结论样本太小。
6. **修盯市日期错配**：组合估值把个股与基准对齐到同一个交易日。

## 7. 处置记录（行业分散上限）

**2026-10-12：`select.maxPerIndustry` 从 99（关闭）→ 3。**

- 问题（本文 §5.1）：上限关着 → 组合可把半仓押在同一板块（10-08 起 3 天，十几个名字挤在
  存储/半导体/算力硬件）。
- 根因之一：行业源（逐只东财 `f127`）**不稳定且不可复现**（实测抽样 51 只里 42 只返回 `'?'`），
  当年索性关掉上限。进一步，东财行业粒度**过细**（半导体 / 通用设备 / 其他电子 / 军工电子 /
  通信设备 / 航空装备是 6 个不同行业，却同属 AI 硬件一个板块），即便开着细分口径上限也拦不住板块扎堆。
- 改动：
  1. 新增本地冻结映射 `web/config/industry-map.json`（**申万一级**，31 类，1886 只），
     由 `web/scripts/build-industry-map.js` 从东财 `datacenter-web` F10 报表一次性生成；
     `web/lib/industry.js` 选股时**只读本地映射**（f127 仅兜底），离线可复现。
  2. `selectByFactors` 的分散上限改为作用在**一级大类**（`coarseSector`）。
  3. 定值 `= 3`：单一大类 ≤30%、强制 ≥4 个板块。
- 定值依据：生产口径扫 `{99,4,3,2}`（训练 2024-04-17~12 / 验证 2025，**未用 2026**）。
  `4` 与关闭几乎无差；`3` 验证段均值几乎不变（1.84→1.79）、最差月略优（-5.88→-5.59)；
  `2` 最差月最好但均值代价明显（训练 0.98→0.78）。留档：
  [`docs/runs/B/train-20261012T073557/`](../B/train-20261012T073557/summary.md)。
- 未解决（建议项 §5.2/5.3 仍在）：B 的下跌 regime 护栏、评估口径改组合等权。
  本次**不含**这些改动（节后基日已由 §8 处置）。

## 8. 处置记录（节后基日：标注 + 评估分档）

**2026-10-12：把「基日 → 生效日」的信号滞后显式化（不改任何交易行为）。**

- 问题（本文 §3.5）：盘前刷新的价格基准恒为上一交易日收盘；长假归来首个交易日的推荐
  特征全部取自节前最后交易日。以 10-08 为例：`basisDate = 2026-09-30`，入场却在 10-08 开盘
  —— 交易日只隔 1 个，但**自然日跨 8 天、其中休市 7 天**（本文原写"5 个交易日"有误）。
  更进一步，刷新时事件窗口末端是运行日（纳入隔夜/假日公告），于是出现
  「**价格读数陈旧 + 事件最新**」的不对称，对均值回归策略最不利。
- 改动（**A：标注**，零交易风险）：
  1. `web/lib/trading-days.js` 新增 `tradingLag(from,to)`（自然日 / 休市日）与
     `STALE_CLOSED_DAYS = 3`（普通周末 = 2，小长假起 = 3）。
  2. 推荐 payload 增 `signalLag: { calendarDays, closedDays, stale }`；`lib/recommend.js` 写盘时
     带上，`enrichRecommend` 读时补算（旧文件也能显示）；`forwardArchive` 一并归档。
  3. 推荐页在「基准日收盘」后按 `stale` 显示琥珀徽标「⏳ 节后首日 · 信号滞后 N 天」。
- 改动（**B：评估分档**）：`eval-backtest.js`（回看口径）与 `eval-ab-combo.js`（前瞻口径）
  单列「节后首日 vs 平常日」一档，逐日明细里陈旧日打 `⏳`，回答"这些天是否更差"。
- 改的是**可见性**，不动选股/买卖。C（节后降暴露）或 D（顺延一天建仓）若要做，属**可训练
  参数**，须另走训练窗选择 + 留档（§6/§7），且样本仅 ~10 个节后首日，只能当风控开关。
- 冒烟：`2024-10-08`（训练窗内最近的国庆首日）实测单日 +7.5% 超额，**这一档并非必然更差**；
  结论要等前瞻样本（`recommend-*-fwd`）攒够 ≥10 个节后首日。
