# 事故复盘：模拟持仓三条曲线 10 月全平（2026-11-05）

## 现象

- 「模拟推荐持仓」dual / A / B 三条曲线，09-30 ~ 11-04 全部是 0%，只有 11-05 一个点跳到 +3.37%。
- 页面数据来自 `/api/positions`；用户 19:44 反馈。

## 根因

1. 18:30 为部署 A 链退出修复重启服务，进程内 `positions:all` 缓存被清空。
2. 重启后首次重算时，K 线缓存不完整 / 上游返回短序列；`computeChain` 对 atOpen 买入取不到开盘价时**直接 `splice` 丢弃**。
3. dual/B 的 22 个推荐日只剩 11-05 一天（10 笔）；A 只剩 09-30 / 10-08 / 10-09 / 11-05（40 笔）。
4. 盘后 `recommendTtlMs` = 12h，错误结果被冻住到次日 06:30。

## 证据

- 事故时 API：dual 10 笔、A 40 笔 → 11-05 之前没有持仓，曲线全 0。
- 同一份 `positions.js` + 当前完整 K 线重算：三条链各 210 笔，曲线完整。
- `web/lib/positions.js` 最后一次改动是 2026-10-12，事故不是持仓代码本身的逻辑改动。

## 修复

1. `web/lib/kline-cache.js`：上游短序列不覆盖已有长历史，按日期合并并保留原长度；上游失败保留旧缓存。
2. `web/lib/positions.js`：atOpen 买入开盘价缺失时，回退当日收盘 → 最近收盘 → 推荐快照价；彻底无价才丢弃，并返回 `pricing.approxBuys / droppedBuys`。
3. `buildPositionsAll`：缓存改为**带数据指纹**（recommend / actions / kline-cache 目录 mtime），数据一变立即重算，不再被 12h TTL 冻住。
4. 盘前（< 09:30）排除数据源「今天」的占位 K 线，避免曲线/日历出现假点。

## 验证（2026-11-05 盘后）

- `asOf=2026-11-05`，22 个交易日，三条链各 **210 笔**买入，`pricing` 均为 0 / 0。
- dual：**-6.76%**（ai -6.81%）
- A：**+0.54%**（ai **+1.30%**）
- B：**-6.76%**（ai -6.92%）
- 沪深300：**-5.60%**
- 历史回看：11-04 为 200 笔 / -6.94%；11-03 为 190 笔 / -9.27%。

## 附注

- A 的 `ai` 线在 11-04 补跑 17 笔退出后为 **+1.30%**，与 `orig +0.54%` 的差异来自 AI 决策本身，不是曲线 bug。
- 事故修复只动缓存与买入价兜底；**没有改**选股、持有期、线上 A/B/dual 参数。
