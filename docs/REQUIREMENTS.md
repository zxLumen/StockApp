# 要求（REQUIREMENTS）· 单一事实源

> 本文件是 StockApp「推荐系统」研发的**唯一要求事实源（single source of truth）**。
> 任何要求的新增/变更，**必须**先改这里，再改代码与其它文档。
> 目的：**防止记忆退化** —— 站长的每条要求都落在此，日后不再靠回忆。
>
> 最近更新：2026-10-06。

---

## 0. 总目标与定位

- 产品是「每日推荐」：每个交易日收盘后产出 Top10 推荐，前端「推荐」页展示。
- 定位：**仅供研究参考，不构成投资建议**（前端已声明）。
- 系统由**三套方案**组成，**各自独立、各自从头训练、各自留档**：
  - **A-only**：成交额池 + LLM 选股/解读。
  - **B-only**：稳健池 + 客观多因子。
  - **双链路**：按当日市场状态（tilt）在 A / B 之间择一。
- 线上采用**双链路模式**；本要求约束的是"参数怎么来"，**模式保持不变**。

## 1. 数据划分（硬性）

| 集合 | 区间 | 用途 |
| --- | --- | --- |
| **训练 Train** | 2024-01-01 ~ 2024-12-31 | 拟合一切可训练参数 |
| **验证 Val** | 2025-01-01 ~ 2025-12-31 | 选型确认（不反复搜） |
| **测试 Test** | 2026-01-01 ~ 2026-12-31 | **完全留出**，冻结参数后只评一次 |
| **前瞻 Forward** | 2026-10 之后（真实每日） | 最终、无条件干净的证据 |

- **2026 必须完全排除在"模型"之外**：训练、验证、调参、prompt 开发**一律不得**使用 2026 数据。
- **测试集红线**：参数冻结**之前**，不得计算 2026 的任何汇总/指标（防止"看一眼再回去改"）。

## 2. Point-in-time 红线（"不用未来数据"）

**每一步（特征、拟合/finetune、prompt、评估）都只能用 ≤ 决策日 D 的数据：**

- 日K：一律截断到 `≤ D`（`computeFactors` / `sliceBars` 语义）。
- 财务：`NOTICE_DATE ≤ asOf`；越界**必须**报错，不得静默过滤（见 `lib/finance.js:latestFinance`）。
- 公告 / 新闻：`time ≤ D`。
- 训练 / 验证 / 测试**共用同一套 `asOf` 注入**；**禁止**任何"读全量数据"的旁路入口。

## 3. 记忆污染的处理边界（站长定）

- **LLM 自身预训练里的知识（含对历史行情的记忆）—— 不管**（超出我们可控范围）。
- **只保证我们可控范围内不引入"未来"信息**：特征、拟合/finetune、prompt 开发、评估，
  全部遵守 §2 的 point-in-time 红线。
- 即：**"干净"= 我们的流程无前视/无泄漏**；不要求模型本身"没听过 2024"。

## 4. 参数"不写死"原则（尽量灵活）

- **持仓周期 T+ 不写死**：由**模型按个股情况**自由判断，不锁定为固定档位
  （现状 `normalizeHoldDays` 锁 `{3,5,10,20}` 需去掉）。
- **所有策略参数不写死**：权重、阈值、门控、池子/候选数、初筛规则、prompt 等，
  一律**训练拟合**或**模型按情境决定**，不留魔法常量。
  - 已知硬编码点（待改造）：`DEFAULT_WEIGHTS`、`thr=0.6`、`regimeTilt` 的 lo/hi、
    `OBJECTIVE`（`rank.js`）、`RECOMMEND_DEV_HI`、`poolPages/topCandidates/finalPicks/maxPerIndustry`、
    `holdDays` 归一化、`HIDDEN_RECOMMEND_*`。
- 基础设施参数（并发、缓存 TTL、端口）不属于"策略参数"，可保持固定（非"写死"语义）。

## 5. 评估口径

- 收益结算**按每只票各自选定的持有周期**（模型决定），**不**用固定 T+5/10/20 硬结算。
- 每套方案（A/B/双链路）**各自**在 2025 验证、2026 测试；指标至少含：超额（相对基准）、胜率、逐月分布。

## 6. 留档规范（强制，防记忆退化）

**凡训练 / 验证 / 测试等每个阶段，其过程与结果都要留档：**

- 统一入口：`docs/REQUIREMENTS.md`（本文件，要求）+ `docs/DATA-SPLIT.md`（划分）+ `docs/runs/`（每次运行）。
- 每次运行目录：`docs/runs/<A|B|dual>/<train|val|test>-<时间戳>/`，至少含：
  - `config.json`：参数、数据窗口、`asOf` 纪律说明。
  - `command.txt`：完整命令（可复现）。
  - `result.json`：指标（机器可读）。
  - `log.txt`：原始日志。
  - `summary.md`：结论 + **当时可见的数据范围** + 决策。
- 旧规划归档在 `docs/archive/2026-10/`（只读留证）。

## 7. 生产与上线

- 三套方案在**本地**训练/验证/测试；双链路模式上线。
- 上线 = `git push main` → CI 自动部署（`docs/DEPLOY` 见 README）。上线前需站长授权。
- 参数变更属于生产行为，必须留档（§6）。

## 8. 红线清单（汇总，勿违反）

1. 2026 数据**不得**参与任何训练/验证/调参/prompt 开发。
2. 任何一步**不得**使用 `> 决策日` 的数据（财务/公告/新闻/日K 皆然）。
3. 参数冻结前**不得**查看测试集汇总。
4. 参数**不写死**（策略类）。
5. 每个阶段**必须留档**。
6. 回测产物**不得**写进 `data/recommend/`（会顶掉真实历史）。
